# 摄像头模块局域网接入验证

实现前确定以下失败场景：

- 配网完成后模块未获得地址、Mac 与模块不在同一网段、AP 隔离、模块离线或发现超时：报告未发现，不能把 USB 摄像头或其他网络设备当成目标。
- 模块 IP 经 DHCP 改变：重新通过广播发现并读取响应源地址，使用完整设备 ID 确认身份，不能写死或仅依赖旧 IP。
- UDP 响应为空、过长、不是 JSON、缺少结果或设备信息、状态非零、设备标识不匹配：拒绝响应。
- 响应来自组播、广播、回环地址或本机地址，源地址不属于发送发现请求的本地网段，源端口不是合法端口，或监听端口不是 20190：拒绝响应。
- 设备经过 NAT 时，响应正文中的 ipaddr 可以与实际 UDP 源地址不同；按原 SDK 使用实际源地址。支持 JSON 和 Qp/PPRPC 2600 二进制发现响应。
- 缺少或格式不正确的局域网签名：停止认证，不尝试猜测密码。
- TCP 连接拒绝、连接超时、半包、连接中断、超长帧、无效或非规范 varint、不支持的帧类型、加密方式、RPC 类型：报告具体阶段失败。
- 应用更新后 macOS 刷新本地网络授权缓存，首次连接暂时返回 EHOSTUNREACH：在限定时间内创建新套接字重试，取消仍须立即生效。
- AES 解密失败、填充不正确、握手命令或序号不匹配、设备返回非零状态、缺少或过长的会话密钥、SyncConn 不确认：认证失败。
- 等待发现或认证时取消、重复发起连接、退出：停止当前连接，忽略旧请求的回调，关闭套接字。
- 已通过发现、认证和同步但没有视频帧：只能报告网络认证完成，不能报告实时预览成功。
- 设备签名和会话密钥只能在内存中使用，不写入日志或测试报告。

`module-network-check.sh` 验证独立保留的报文字节、解析边界和响应来源校验。静态向量来自官方 APK 的 ARM64 编码器逐指令还原，不代表真实模块取流已经通过。测试产物位于 `.build/module-network-check/`。

真实 E2E 还需要模块完成 2.4 GHz Wi-Fi 配网：按完整设备标识过滤发现，获得模块应答，完成 TCP 20190 的 LanAuth 和 SyncConn，再以真实视频帧和可解码文件验证取流。物理断电、AP 隔离和无线凭据错误需要在真实网络中验证。

媒体实现前增加以下场景：

- 实时预览必须复现官方 App 的 VideoPlay 2610（通道 0、画质 0、速度 0，空 protobuf 正文）；不能用 AppVideoPlay 561 的对讲路径替代预览。
- TCP 同一读取含多个包、包头和包体分多次读取、非规范长度、超长帧：正确分离或拒绝，不能拼接出假帧。
- AVPacket 的 8/9/A 头格式、可选源、文件标识、扩展区和偏移不完整，密文前缀不对齐或超过包体，使用未支持的加密方式：明确拒绝。
- 媒体 AES 密钥必须由真实会话密钥、序号、时间戳和通道派生；不能用固定示例密钥接收实际设备数据。
- H.264 未收到 SPS/PPS、错误密钥导致的无效 NAL、空包、帧尺寸变化：不得把无效数据报告为画面。
- MJPEG（格式 4）必须解码为真实像素缓冲区并保留时间戳；空图、截断 JPEG、无效图像、过大尺寸、不支持的片段偏移必须拒绝，文件回放来源必须忽略。
- AV 分片以偏移 1 开始，顺序中间片后由 255 结束；分片可共用序号但具有不同时间戳。缺少首片、缺片、错误序号和过大组帧必须丢弃；重复中间片不能重复追加，新首片必须替换不完整旧帧，各通道互不混合，完成组帧后才能按序号去重。
- 报文序号重复或倒退、断网、首次视频超时和取消：忽略重复帧或结束连接，并保持网络认证与真实画面状态分离。
- 合成 H.264 和 JPEG fixture 必须经系统解码出预期像素尺寸。此验证不能替代摄像头实机 E2E。
